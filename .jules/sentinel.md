## 2024-03-29 - Missing Security Headers & Reverse Tabnabbing Risk
**Vulnerability:** The Angular SSR Express server (`server.ts`) lacked fundamental HTTP security headers (HSTS, X-Frame-Options, X-Content-Type-Options, X-XSS-Protection). Additionally, multiple external links opened in new tabs (`target="_blank"`) without the `rel="noopener noreferrer"` attribute, exposing the application to potential reverse tabnabbing attacks.
**Learning:** Even simple SSR implementations require manual security header configuration. When using Angular Universal/SSR with Express, default security protections must be explicitly added as middleware. Moreover, external links in component templates are a common vector for tabnabbing if not consistently sanitized.
**Prevention:** Always include a security middleware (like `helmet` or custom headers) when bootstrapping an Express server. Implement linting rules (e.g., `eslint-plugin-angular` or native Angular template checks) to enforce `rel="noopener noreferrer"` on all `target="_blank"` anchor tags across the codebase.
