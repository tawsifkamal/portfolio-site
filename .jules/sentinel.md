## 2026-03-11 - Add Basic Security Headers to Express Server
**Vulnerability:** The Angular SSR Express server in `server.ts` was leaking the framework identity via the `X-Powered-By: Express` header and missing standard security headers (`Strict-Transport-Security`, `X-Frame-Options`, `X-Content-Type-Options`), which could facilitate fingerprinting, clickjacking, and MIME-sniffing attacks.
**Learning:** Default Express configurations do not enforce security headers. In a standalone setup where no reverse proxy (like Nginx) manages headers, the Node.js server itself must set them. Additionally, accessing browser-specific globals like `window` during Prerendering/SSG can cause builds to fail if not guarded, though this specific fix pertains to backend server configuration.
**Prevention:** Always use tools like `helmet` or explicitly set security headers for Node/Express backends, and ensure `disable('x-powered-by')` is called. For Angular SSR, apply these middleware early in the `app()` function.
