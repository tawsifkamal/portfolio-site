## 2026-04-12 - [MEDIUM] Add security headers to Express responses
**Vulnerability:** The Angular SSR server running via Express (`server.ts`) did not enforce fundamental HTTP security headers, leaving the application vulnerable to common attacks such as clickjacking (`X-Frame-Options`), MIME-sniffing (`X-Content-Type-Options`), and basic reflected cross-site scripting (`X-XSS-Protection`), while also unnecessarily leaking backend technology information via the `x-powered-by` header.
**Learning:** In a full-stack Angular application utilizing Server-Side Rendering (SSR) via Express, the web server layer must be explicitly configured to enforce HTTP security headers. Standard Angular CLI templates do not inherently generate secure Express server configurations out-of-the-box, meaning developers must manually intervene.
**Prevention:** Always implement a custom middleware in the `server.ts` file immediately after instantiating the Express app to set basic security headers (`Strict-Transport-Security`, `X-Frame-Options`, `X-Content-Type-Options`, `X-XSS-Protection`) and invoke `server.disable('x-powered-by');`. Consider using libraries like `helmet` for more comprehensive header management if external dependencies are permitted.
